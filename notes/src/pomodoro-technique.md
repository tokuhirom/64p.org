# ポモドーロ・テクニック

Francesco Cirilloが1980年代末に考案した時間管理手法。作業を25分の集中区間(pomodoro)に区切り、その間に割り込みを入れないことで、注意の連続性を確保する。 #productivity #task-management

## 基本サイクル

1. やることを1つ決める
2. タイマーを25分にセットする
3. 鳴るまでそのタスクだけをやる
4. 3〜5分の短い休憩を取る
5. 4ポモドーロごとに20〜30分の長い休憩を取る

名前は、Cirilloが学生時代に使っていたトマト型のキッチンタイマー(伊: pomodoro = トマト)に由来する。

## ポモドーロは不可分

この手法の要は「25分」という長さ自体ではなく、**1ポモドーロは分割できない**というルールにある。途中で中断が入った場合、そのポモドーロは中止して最初からやり直すか、中断のほうを先送りするかの二択になる。「半分だけやったポモドーロ」は存在しない。

割り込みは2種類に分けて扱う。

- **内的中断** — 自分の中から湧く「あれも調べたい」「メールを見たい」。思いついた内容だけを紙にメモして、ポモドーロが終わってから処理する。
- **外的中断** — 他人からの声かけ・着信。その場で対応せず、相手に伝える → 交渉する → 予定に入れる → 後でこちらから戻る、という手順で先送りする。

Cirillo自身は機械式タイマーと紙・鉛筆を使うローテクなやり方を推奨している。ゼンマイを巻く動作、カチカチという音、鳴る音という物理的な合図が集中の切り替えを助けるという理由。

## 他手法との関係

[[gtd|GTD]]やZTDが「何をやるか」を決める仕組みなのに対し、ポモドーロは「決まったものにどう向き合うか」を扱うため、レイヤーが違って併用しやすい。[[time-blocking|タイムブロッキング]]がカレンダー上の枠を確保するのに対し、ポモドーロはその枠の中の集中の質を管理する、という関係になる。[[most-important-tasks|MIT]]で決めた本日の最重要タスクに対して何ポモドーロ充てるか、という形で見積もりの単位としても使える。

## [[productivity-methods|個人生産性メソッド]]の中での位置づけ

実行系のうち「どう向き合うか(集中)」を担当する。何をいつやるかは決めないので、他のどの手法の下にも敷ける。
