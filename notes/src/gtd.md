# GTD (Getting Things Done)

David Allenが2001年の同名書籍で提唱した個人向けタスク管理手法。中核の主張は「頭は考えるための道具であって、覚えておくための道具ではない」。気になっていること(open loops)をすべて頭の外の信頼できるシステムへ追い出し、認知的な負荷を消すことを目指す。Allenはその状態を "mind like water"(水のような心)と呼んでいる。 #productivity #task-management

## 5つのステップ

| ステップ | やること |
|---|---|
| **Capture**(捕捉) | 気になっていること・依頼・アイデアを、判断せずに全部inboxへ入れる |
| **Clarify**(明確化) | 1件ずつ「行動可能か?」を判定する。可なら「次に取る物理的な行動(next action)」まで分解し、不可なら参照資料・someday/maybe・削除へ振り分ける |
| **Organize**(整理) | next actions / projects / waiting-for / someday-maybe などのリストに配置する |
| **Reflect**(レビュー) | 週次レビュー(weekly review)でリストを最新化する |
| **Engage**(実行) | 文脈・使える時間・エネルギー・優先度からその場で選んで実行する |

## 特徴的なルール

- **next action** — 「Xについて考える」ではなく「Yさんにメールを書く」まで具体化する。曖昧なタスクが手つかずのまま残るのは、次の一手が物理的な行動になっていないからだ、という診断。
- **2分ルール** — Clarifyの段階で2分以内に終わると分かったものは、リストに載せずその場で片付ける。管理コストのほうが実行コストを上回るため。
- **weekly review** — システムを信頼できる状態に保つための定例整備。ここをサボるとリストへの信頼が崩れ、結局頭の中で覚え直すことになるので、GTDの中では最も要になる工程とされる。
- **Horizons of Focus** — 目の前のnext actionから人生の目的まで、6段階の高度でコミットメントを眺める枠組み。

## 置き場所の一元化との関係

Captureの出発点にある「inboxを用意して、気になったことは全部そこに入れる」という設計は、[[one-pocket-principle|ポケット一つ原則]]そのもの。「必ずそこにある」という存在定理が成り立つ入れ物を1つ作ることが、頭から追い出す前提になっている。

## よく指摘される弱点

- セットアップと維持のコストが高い。特に週次レビューが重く、ここが回らなくなって崩壊するパターンが多い。
- 習慣化についてはほとんど扱っていない。仕組みは与えるが「そもそも取りかかれない」問題には答えない。
- 優先順位付けの仕組みが弱い。next actionsリストは平坦に増えていくため、量が増えると選ぶこと自体が負担になる。

## 代替・周辺の手法

GTDは「実行系」(タスクとコミットメントの管理)の手法なので、代替を探すときは同じ実行系なのか、そもそも目的の違う知識管理系なのかを区別すると整理しやすい。

### 実行系(GTDの直接の代替)

- **ZTD (Zen to Done)** — Leo Babautaが「GTDは複雑すぎるうえ、"doing"への焦点が足りない」という問題意識から組み替えたもの。システムではなく10個の習慣(最小構成では4つ)を1つずつ身につける形にしている。GTDのセットアップコストで挫折した場合の第一候補。
- **Personal Kanban** — To Do / Doing / Done の見える化とWIP制限の2ルールだけ。リストが無限に伸びるというGTDの弱点に直接効く。
- **バレットジャーナル** — 紙のノートにrapid loggingし、月次・日次でmigration(次のページへの書き写し)を行う。書き写しが面倒なタスクが自然に脱落する仕組みが、優先順位付けを兼ねている。
- **アイゼンハワー・マトリクス** — 緊急度×重要度の4象限。手法というより判断のフレームで、GTDの優先順位の弱さを補う形で併用されることが多い。
- **Autofocus (Mark Forster)** — 1本の長いリストを巡回し、「今やりたい」と直感的に感じた項目を取る方式。GTDの文脈別リスト分割という前提のほうを外しにいくアプローチ。
- **タイムブロッキング** — リストではなくカレンダーの枠に仕事を置く。「リストはあるが着手する時間が確保できない」型の失敗に効く。

### 知識管理系(代替ではなく相補)

- **PARA** (Projects / Areas / Resources / Archives) — Tiago Forte。タスクではなく情報を「今どれくらい行動に近いか」で分類する。
- **[[zettelkasten|Zettelkasten]]** — 原子的なノートをリンクで繋いで思考を育てる。タスク実行の用途には向かない。

実務では実行系から1つ、知識管理系から1つを組み合わせる使い方がよく紹介される。1つのシステムに全部やらせようとすると破綻する、という点は各手法の比較記事でおおむね共通している。
