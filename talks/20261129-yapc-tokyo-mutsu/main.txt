----
*GC
----
最初は Arc (参照カウント) だけ
→ 循環参照がリークする
----
Raku では循環参照は日常
- 再帰クロージャ
- 親子オブジェクト
- Promise / Supply
----
GC が無いインタプリタは
誰も使わない
----
選択肢
- tracing GC (moving)
- 参照カウント + cycle collector
----
選んだのは
**非移動 (non-moving)
参照カウント + cycle collector**
(ADR-0001, 2026-06-27)
----
なぜ？
→ Rust の Value があちこちのスタックに生で転がってる
→ moving GC にすると全部追跡しないといけない
→ 非移動なら JIT も楽
----
7/5 GC デフォルト on

バックエンド

GC → NaN-boxing → JIT
の順番を最初に決めた
----
非移動 GC だから
JIT はスタックマップも
write barrier もいらない

起きること
----

----

→ GitHub Actions 無料枠の同時 20 ジョブ
→ PR ジョブが 5〜15 分待ち
----
→ 重いテストは PR から外して main で毎時
----
main が赤くなった
→ 約20 の PR がそれぞれ勝手に修正を push
→ runner 飽和、また衝突
----
→ 「main is red」issue を1つ立てて
直すのは1人だけ
----
flaky test
→ 調べたら大半は決定的なバグだった
- テストのポート衝突
- Lock.protect の lost update
----
`while pgrep -f "make lint"`

----
`pkill -f "make test"`
→ 自分のシェルを殺す
----
